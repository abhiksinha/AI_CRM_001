# High-Level Architecture: Predictive CRM

This document outlines a high-level architecture for a Predictive CRM. This design extends a traditional CRM by integrating a dedicated AI/ML service to generate predictions and insights from customer data.

### Core Principles

*   **Decoupled Services:** Services are independent and communicate via APIs and events, allowing them to be developed, deployed, and scaled separately.
*   **Centralized Data for AI:** A central data warehouse is used to consolidate data from all services, providing a clean, unified source for training machine learning models.
*   **Actionable Insights:** The goal is not just to present data, but to provide predictive insights directly within the user's workflow to guide their decisions.

### Architectural Components

Here is a breakdown of the major components and their roles in the system.

```
+----------------+      +-----------------+      +----------------------+
|   CRM Frontend |----->|   API Gateway   |<---->|  Core CRM Services   |
|      (Web)     |      +-----------------+      |  (Go: UserService,  |
+----------------+               ^               |   DealService, etc.) |
       ^                       |               +----------+-----------+
       |                       v                          |
       |         +-------------------------+              | (Transactional DB)
       |         | AI / Prediction Service |              v
       |         |        (Python)         |      +-----------------+
       |         +-------------+-----------+      |    PostgreSQL   |
       |                       ^                  +-----------------+
(Display Predictions)          | (Predictions)
       |                       |
       |   +-------------------+------------------+
       |   |             Data Warehouse           |
       +-->| (e.g., BigQuery, Redshift, Snowflake)|
           +-------------------+------------------+
                               ^
                               | (ETL/ELT)
                               |
           +-------------------+------------------+
           |      Event Bus / Data Streaming      |
           |      (e.g., Kafka, RabbitMQ)         |
           +--------------------------------------+
```

### Component Breakdown

1.  **CRM Frontend:**
    *   The user interface for the CRM. It's the primary way users interact with the system.
    *   It consumes data from the API Gateway and will display not only customer data but also the predictions generated by the AI service (e.g., "This lead has a 90% chance of closing").

2.  **API Gateway:**
    *   A single entry point for all client requests.
    *   It routes requests to the appropriate backend service (e.g., a request for customer data goes to the `UserService`, while a request for a prediction might go to the `AI Service`).
    *   Handles cross-cutting concerns like authentication, rate limiting, and logging.

3.  **Core CRM Services (Go):**
    *   These are the backbone of the standard CRM functionality.
    *   `UserService`: Manages customer and contact information.
    *   `DealService` (or `TxnService`): Manages sales pipelines, deals, and transactions.
    *   Each service has its own transactional database (e.g., PostgreSQL) to store its operational data.
    *   When data is created or updated, these services publish events to the **Event Bus**.

4.  **Event Bus / Data Streaming (e.g., Kafka):**
    *   A messaging system that decouples the Core CRM Services from the Data Warehouse.
    *   When a user is updated in `UserService`, it publishes a `user-updated` event. This allows other services to react to the change without being tightly coupled.
    *   This is the primary mechanism for getting real-time data into the data warehouse.

5.  **Data Warehouse:**
    *   A specialized database designed for analytics and business intelligence.
    *   It consolidates data from all services into a single source of truth for analysis. An ETL (Extract, Transform, Load) process consumes events from the Event Bus and loads them into the warehouse.
    *   This historical and aggregated data is perfect for training machine learning models.

6.  **AI / Prediction Service (Python):**
    *   This is the "predictive" engine of the CRM. It runs independently of the core services.
    *   It reads data from the Data Warehouse to train and run its machine learning models.
    *   **Key Models to Develop:**
        *   **Lead Scoring:** Predicts the likelihood of a lead converting into a customer.
        *   **Churn Prediction:** Identifies customers who are at high risk of leaving.
        *   **Customer Lifetime Value (CLV):** Predicts the total revenue a business can expect from a single customer account.
    *   It exposes its own API endpoints for the rest of the system (via the API Gateway) to query for predictions.

### Example Workflow: Predictive Lead Scoring

1.  A new lead is created in the CRM via the **Frontend**.
2.  The **API Gateway** routes the request to the **UserService**.
3.  The **UserService** saves the new lead to its database and publishes a `lead-created` event to the **Event Bus**.
4.  An ETL process picks up the event and inserts the new lead's data into the **Data Warehouse**.
5.  The **Frontend**, after creating the lead, makes a request to the **API Gateway**: "What is the score for this new lead?"
6.  The **API Gateway** forwards the request to the **AI / Prediction Service**.
7.  The **AI Service** uses its trained Lead Scoring model (and potentially queries the **Data Warehouse** for more context) to calculate a score.
8.  The score is returned to the **Frontend** and displayed to the user, who can now prioritize this lead accordingly.
